# Province renaming in game (EU4-style): feasibility

Date: 2026-10-19. Status: **idea, not a card yet.** Nothing here has been
checked in Ghidra or in game; everything below is from script knowledge and
the existing project notes, marked with its confidence.

## 1. What the engine already offers

- Script effects `change_province_name = "..."` (province scope) and
  `change_region_name = "..."` (state). HPM/TGC use them for historical
  renames (e.g. Constantinople -> Istanbul). **I** (known from mods; not
  checked against TGC v2.5.2 with `tgc_scan.py` yet).
- The new name is believed to be stored in the save. **?** (to confirm in a
  save file).
- Limitation: the name is a **fixed string in script**. Script cannot read
  text typed by the player.

## 2. Route A: script only (works without the DLL, R6)

- A province decision/event offers a fixed list: historical names, cultural
  names, "revert to original".
- Multiplayer-safe by construction (script effect).
- Not free text. Scales only if generated by a tool (like `gen_laws.py`)
  from a data file in `data/`.
- Size: small (days): generator + localisation (`tgcx_` keys, R4).

## 3. Route B: free text (needs the DLL)

- Native edit-box widget exists (save-game name, chat). The DLL adds a
  "Rename" button to the province window that opens one.
- Applying the name, two options:
  1. **Write the province's name directly.** Easy in single player; breaks
     R5 for multiplayer (deferred by D5, but would need fixing later).
  2. **Through an engine command.** No known `C*Command` renames a
     province; check the 74 commands in `docs/rtti-classes.md`. If none
     exists, MP-safe means our own synchronised channel: hard.
- Unknowns (Ghidra research):
  - where `CProvince` holds its name (localisation key `PROV<id>` or its own
    string);
  - the function behind `change_province_name` (reusing it is the cleanest
    route);
  - whether the map label cache refreshes after a rename.
- Size: single player medium (edit-box GUI + finding the function);
  MP-safe large and uncertain.

## 4. Where it fits

- **Cosmetic** package (D15). Base-independent, like Army.
- R10: a mockup board is needed before implementation.

## 5. Proposed next step

A research card: locate `change_province_name`'s handler and the province
name storage in Ghidra, check the command list, confirm save persistence.
Decide route A, B or both afterwards **[user]** (R9).
